## Система підписання документів (Waiver)

### Що це?
Електронна форма згоди, яку клієнт підписує перед процедурою татуювання. Юридичний документ, що підтверджує:
- Повноліття клієнта (18+)
- Відсутність медичних протипоказань
- Тверезість
- Ознайомлення з правилами догляду
- Згоду на процедуру

### Як це працює (User Flow)

#### Крок 1: Відкриття деталей запису
1. Адміністратор/майстер відкриває календар
2. Клікає на запис (appointment)
3. Відкривається Drawer з деталями запису
4. Переходить на вкладку "Документи"

#### Крок 2: Підписання (якщо не підписано)
1. Бачить повідомлення "Документ не підписано"
2. Натискає кнопку "Підписати документ"
3. Відкривається новий Drawer з двома кроками:

**Крок 2.1: Документ**
- Клієнт читає текст документа (інформована згода)
- Ставить галочки на всіх обов'язкових пунктах:
  - ✅ Підтверджую, що мені виповнилось 18 років
  - ✅ Підтверджую відсутність протипоказань
  - ✅ Підтверджую тверезість
  - ✅ Ознайомлений з правилами догляду
  - ✅ Даю згоду на процедуру
- Натискає "Далі до підпису"

**Крок 2.2: Підпис**
- Малює свій підпис на canvas (працює і на touch-пристроях)
- Може очистити і перемалювати
- Натискає "Підписати документ"

#### Крок 3: Підтвердження
1. Документ збережено
2. На вкладці "Документи" тепер показується:
   - ✅ "Документ підписано"
   - Дата і час підписання
   - Зображення підпису клієнта
   - Кнопка "Завантажити PDF"

### Технічна реалізація

#### Backend
```
POST /api/waivers/sign
{
  "appointmentId": "uuid",
  "templateId": "uuid",
  "signatureData": "data:image/png;base64,...", // підпис як base64
  "checkboxValues": {
    "age_confirmation": true,
    "health_confirmation": true,
    ...
  }
}
```

#### Що зберігається в БД
- `signed_waivers` таблиця:
  - ID підписаного документа
  - Appointment ID
  - Client ID
  - Template ID (версія шаблону)
  - Signature Data (base64 зображення підпису)
  - Checkbox Values (JSON з відмітками)
  - Client IP (для юридичної валідності)
  - Дата підписання

#### Шаблон документа
- Автоматично створюється для тенанта при першому запиті
- Містить стандартний текст українською
- Підтримує версіонування (можна оновлювати)

## Система оплати (Payments)

### Що це?
Система обробки платежів за послуги тату-салону з повним аудитом транзакцій.

### Типи платежів
| Тип | Опис |
|-----|------|
| `deposit` | Передоплата при записі |
| `service_payment` | Оплата послуги |
| `refund` | Повернення коштів |
| `tip` | Чайові майстру |

### Методи оплати
| Метод | Опис |
|-------|------|
| `cash` | Готівка |
| `card` | Картка (термінал) |
| `split` | Комбінований (частина готівкою, частина карткою) |

### Як це працює (User Flow)

#### Прийом оплати
1. Відкриваєш деталі запису → вкладка "Оплата"
2. Бачиш:
   - Вартість послуги
   - Знижку (якщо є)
   - Вже сплачену суму
   - Залишок до сплати
3. Натискаєш "Прийняти оплату"
4. Відкривається Drawer:
   - Вибір типу (Оплата послуги / Передоплата)
   - Введення суми (швидкі кнопки: 50%, 25%, Повна сума)
   - Вибір методу оплати
   - Для split: окремо готівка і картка
   - Опціонально: чайові
   - Опціонально: коментар
5. Натискаєш "Прийняти оплату"
6. Платіж записується з номером чеку

#### Історія платежів
- Всі платежі показуються на вкладці "Оплата"
- Для кожного платежу видно:
  - Тип (передоплата/оплата/повернення)
  - Сума
  - Метод оплати
  - Дата і час
  - Номер чеку
  - Кнопка "Повернути" (якщо можливо)

#### Повернення коштів (Refund)
1. Знаходиш платіж в історії
2. Натискаєш "Повернути"
3. Відкривається модальне вікно:
   - Сума повернення (не більше оригіналу)
   - Причина (обов'язково!)
   - Метод повернення
4. Підтверджуєш
5. Створюється транзакція типу REFUND
6. Оригінальний платіж позначається як (частково) повернений

### Технічна реалізація

#### Backend Endpoints
```
POST /api/payments/process         - Обробка оплати
POST /api/payments/refund          - Повернення
GET  /api/payments/appointment/{id}/summary  - Підсумок
GET  /api/payments/appointment/{id}          - Історія
```

#### Приклад запиту на оплату
```json
POST /api/payments/process
{
  "appointmentId": "uuid",
  "amount": 4500.00,
  "paymentMethod": "split",
  "paymentType": "service_payment",
  "cashAmount": 2000.00,
  "cardAmount": 2500.00,
  "tipAmount": 500.00,
  "description": "Оплата татуювання"
}
```

#### Що зберігається
- Транзакція з унікальним ID
- Тип і категорія
- Сума (загальна, готівка, картка, чайові)
- Метод оплати
- Хто обробив (processedBy)
- Номер чеку (receipt_number)
- Зв'язок з appointment і artist
- Для refund: зв'язок з оригінальною транзакцією + причина
